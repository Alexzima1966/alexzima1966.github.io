📖 Методология: откуда берется каждое число (без синтетики)

1. Профиль 76-90' по реальным минутам. История последних N матчей команды берется одним запросом POST /Games/query (Condition HomeTeam = X OR AwayTeam = X, Fields Id/Date/ScoreHomeHT/ScoreAwayHT/ScoreHomeFT/ScoreAwayFT, Order -Date), с фолбэком на /Games/list?Team=X&Ended=true. Затем для каждого матча грузятся events через /Games/{id} и кэшируются в IndexedDB навсегда — голы раскладываются по интервалам по фактической минуте (elapsed + extra, с учетом Own Goal). Если events недоступны, матч помечается и профиль получает бейдж «approx» — это честно показывается в UI.

2. Удары в створ — только из реальной live-статистики ApiSaStatistics.shotsOnGoalHome/Away (/Games/{id}, обновление каждую минуту; опциональный ускоритель Pari.ru — 10 сек). Матчи без данных исключаются, «0 (0:0)» не допускается как сигнал.

3. Live-кэфы. /Odds/live/{gameId} (Bet365): из всех маркетов ищется исход «Over {line}», где line = текущий тотал + 0.5. Кэф подставляется в сигнал, журнал и EV-калькулятор. При >12 кандидатах используется /Odds/live-changes/updates-only — обновляем только изменившиеся.

4. Модель вероятности. Ожидаемые голы в оставшееся время: λ = λ(хозяева) + λ(гости), где λ(сторона) = среднее из «голи стороны после минуты m» и «пропущенные соперника после m» (реальные минуты голов), с множителями: срочность счета (1.0–1.22), красные карточки (×1.25/×0.78), атаки замен 55–75' (×1.08), интенсивность ударов/мин (0.85–1.25), xG-приор Glicko /Games/glicko/{id} (0.8–1.3), momentum Flashscore (асимметрия λ 0.85–1.2 по давлению сторон за последние 15 мин). P = 1 − e^(−λ).

5. Value-гейт. Edge = P(модели) − 1/кэф, в процентных пунктах. Сигнал требует edge ≥ порога при доступном кэфе. Если кэф недоступен — сигнал удерживается до 74' и затем помечается «без кэфа».

6. Закрытие сигналов. Пакетно через GET /Excel/Results?id=a,b,c&header=false (до 500 матчей за запрос, CSV), с фолбэком на /Games/list?Id=.... Журнал больше не зависает в «ожидании».

7. Лимиты и безопасность. Rate-limiter с приоритетами (радар → кэфы → история), API-ключ отправляется только на собственный прокси или напрямую — публичные CORS-прокси его не получают. Профили и events кэшируются в IndexedDB.

8. Новое Flashscore API (v0.9.42). Momentum — GET /Ls/GameMomentum?id={flashId}: доля давления хозяев/гостей за последние 15 минут, множитель асимметрии в модели + строка в сигнале + бар в карточке (TTL 2 мин, только кандидаты 2-го тайма, бюджет 6 запросов/цикл). Травмы — GET /Games/injuries?gameId=: один запрос в момент сигнала, попадают в карточку и журнал. Турнирная таблица — GET /Games/season-table?league=&year= (кэш 1 час): ранги/очки/мячи обеих команд в карточке. Составы с рейтингами игроков — GET /Ls/GameLineups?id={flashId}: средний рейтинг и топ-игроки. Форма и средние — GET /Games/last-games-stats?gameId=&limit=: голы/xG/удары/форма за последние N матчей. Все «карточные» запросы идут по требованию при открытии карточки (приоритет 2) и не тратят бюджет радара.

🛡 Как поднять собственный прокси (чтобы не светить API-ключ и обойти CORS)

Первый маршрут программы — /api/sstats?path=… — ваш серверный прокси. Пример Cloudflare Worker:

export default { async fetch(req){ const u=new URL(req.url); const p=u.searchParams.get('path'); if(!p) return new Response('no path',{status:400}); const key=u.searchParams.get('apikey'); const url='https://api.sstats.net'+p+(key?(p.includes('?')?'&':'?')+'apikey='+encodeURIComponent(key):''); const r=await fetch(url,{method:req.method,body:(req.method==='POST')?req.body:undefined,headers:{'Content-Type':'application/json'}}); return new Response(r.body,{status:r.status,headers:{'Access-Control-Allow-Origin':'*','Content-Type':r.headers.get('Content-Type')||'application/json'}});}}

Публичные прокси (corsproxy.io и т.п.) используются только как аварийный fallback и без API-ключа.
