📖 Методика, источники и ограничения v1.4

Историческая base rate: 48 выборочных субботних дат, октябрь 2023 — сентябрь 2025, 48 792 матча обычного времени. Доля матча хотя бы с одним голом во 2-м тайме по HT-счёту: 0 — 75,3%; 1 — 79,4%; 2 — 81,6%; 3 — 82,9%; 4+ — 85,2%. Это частоты исхода в выборке, не ROI и не откалиброванная вероятность для каждой лиги.

Фильтр кандидата: только status 4; нужны подтверждённый счёт HT, минимум 4/6 парных live-блоков, хотя бы один качественный live-признак (xG, SOT или большие моменты) и готовая pre-kickoff интервальная история обеих команд. Обычный путь: base ≥80%, совместный evidence score ≥2/12 и live score ≥1. Override: base ≥75%, совместный score ≥6/12 и live score ≥4. Это эвристические пороги, а не валидированный рейтинг.

  • Base rate по HT-счёту никогда не изменяется от live pressure, Glicko или истории. Сигналу нужен live 1H-пакет и отдельный исторический контекст; значение балла не переводится в процент вероятности.
  • Live pressure объединяет сгруппированные признаки качества моментов, активности, территории, стандартов и контекста первого тайма. Pari/SStats не заменяют отсутствующие данные неявно; xG, xGOT и коэффициентные оценки не смешиваются.
  • Интервальные профили строятся из `/Games/list?Team=…&ended=true` и `/Games/{id}`. Принимаются только status 8 с известными командами/датой/FT-счётом, где количество normal-goal events по teamId и общий итог сходятся с регулярным счётом. Отмены, own goals, пропущенная минута, неизвестная команда события, расхождение счёта и минуты >90 (возможное extra time) делают матч невалидным. 45+ и 90+ остаются в интервале своего тайма по elapsed=45/90; граница профиля — kickoff цели, строгий `< kickoff`, плюс исключение целевого fixture.
  • Профиль показывает два разных знаменателя: частота матчей (match incidence) — доля подходящих матчей, где команда забила/пропустила хотя бы один гол в интервале (делитель n матчей); доля голов (goal share) — доля всех голов/пропущенных голов команды, пришедшаяся на интервал (делитель — голы в окне). Профиль по площадке: n≥6; общий резервный профиль: n≥8. Важно: фактические пороги в алгоритме сейчас 10/10, поэтому отбор строже этого описания; поведение не менялось. Цель — до 12 валидных матчей, жёсткий предел — 40 запросов деталей на команду; история ограничена 20 запросами за цикл и общим лимитером запросов; кэш живёт 24 часа. Это строгая фильтрация, но она не доказывает полную независимую полноту фида для всех лиг.
  • `/Games/glicko/{id}` привязывается к fixture ID. Rating/RD, winProbability и модельные `homeXg/awayXg` не входят в текущий score; проекция показывается отдельно только при timestamp `updated ≤ kickoff`. Sentinel `0001-01-01` или post-kickoff timestamp не проходит point-in-time check. Эти величины никогда не называются live-xG.
  • `/Games/last-games-stats?gameId=…&limit=25&homeAway=true` по OpenAPI усредняет завершённые матчи команд до даты целевого fixture; true означает для хозяев только домашние и для гостей только выездные матчи. Срабатывает один fallback на all-venue режим. `avgScore/avgConceded` — средние голы, `avgOddsXg` — xG-derived-from-odds (не shot-based xG текущего матча). Выборка n и режим отображаются; исторические средние участвуют только в небольшом экспериментальном context score.
  • Каждый live-источник проверяется не более двух раз. Матчи без нужных ключевых HT-показателей не получают Glicko/last-stats probes и исключаются после исчерпания проверок. При достаточном пакете сохраняются status-4 snapshots; финальные матричные статистики не подставляются в live-признаки.
  • Для цены читается только live-рынок «Тотал 2-го тайма — больше 0,5». Сырые Pbase×кэф−1 не являются проверенным value. Снимки сохраняются локально; нужны хронологический holdout, калибровка и ROI/outcome-проверка до любых заявлений о повышении точности.

Аудит полей статистики: таблица деталей поддерживает полный набор из 44 парных показателей SStats ApiSaStatistics, поля Pari TeamStatistics, а также незнакомые числовые/текстовые значения из otherStats. Доступность каждого показателя остаётся зависимой от провайдера и конкретной лиги; «—» означает, что источник не прислал значение, а не ноль.

Как читается xG: сначала используются обе стороны expectedGoalsHome/Away; если полной пары нет — парные calculatedXgHome/Away с явной пометкой расчётной оценки; затем проверяются явные xG-ключи otherStats. Смешанные модели между командами не суммируются. xGOT, xGOT против, Glicko-xG, предматчевые средние и итоговая статистика не выдаются за live-xG перерыва.

Использование признаков: xG/xGOT/большие моменты сгруппированы в семейство качества; удары/штрафная — в семейство активности; опасные атаки/атаки/пасы в финальную треть — в территориальное семейство; стандарты имеют ограниченный вклад. Так снижается повторный счёт коррелирующих метрик. Оборонительные и вратарские поля сохраняются как контекст; одна лишь их высокая величина не даёт положительный бонус.

API ограничен: без ключа программа работает консервативно (до 28 запросов/мин), с ключом — мягкий лимит 130/мин, жёсткий 150/мин; при 429 включается пауза.
